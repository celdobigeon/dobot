Commande temps réel

Piloter le robot ligne à ligne : chaque appel bouge tout de suite et rend la main à l'arrivée. C'est l'outil des scripts interactifs — une cible tapée au clavier, demain une caméra. Les neuf exemples commentés, la référence de la classe Commande, le mode continu tel qu'il a été mesuré sur la machine, et ce qui reste à vérifier.

Section 01Le principe : chaque ligne bouge tout de suite

Deux façons de piloter le même robot, avec les mêmes verbes — movj, movl, movc, repli, ventouse — et les mêmes cibles. Ce qui change, c'est le moment où le robot bouge.

Pilote — fiches 2 et 3Commande — cette fiche
robot.movl(T) ajoute une ligne au programme ; rien ne bouge le robot y va tout de suite ; l'appel rend la main une fois le mouvement fini
Quand ça bouge à simuler() ou executer_sur_robot() : tout le programme, d'un bloc à chaque appel, un mouvement à la fois
Point de départ la position que le script a calculée la posture lue sur la machine juste avant chaque mouvement
Relecture resume(), controler(), l'animation : on relit avant de lancer aucune : des garde-fous contrôlent chaque mouvement avant son départ
Réagir entre deux programmes entre deux lignes : pose(), entree(), input(), plus tard une caméra
Enchaîner sans arrêt le lissage n'existe pas en point à point sur le contrôleur : le robot réel s'arrête à chaque point une liste de cibles part en trajectoire continue (section 6)
from dobot_sim import Commande, cible

with Commande(simulateur=True, robot=False, vitesse=40) as robot:
    robot.movj(cible(220, 0, 80))        # le script attend ICI l'arrivee
    x, y, z, r = robot.pose()            # lue sur la machine, pas supposee
    if z > 50:
        robot.movl(z=40)                 # descente verticale : x, y, r gardes
    robot.ventouse(True)

Le bloc with referme la liaison tout seul à la fin, même après une erreur ou un Ctrl+C : c'est la forme recommandée. En console interactive, on peut aussi écrire robot = Commande(...), puis robot.fermer() à la fin (section 4).

Lequel choisir ?

Pilote Le cycle est connu d'avance : on l'écrit, on le relit, on le simule en entier, on le rejoue. C'est la forme de tous les TP de programmation, et la plus sûre.
Commande La suite dépend de ce qui se passe : une touche, un capteur, une position mesurée, une image. Aussi pour régler un poste pas à pas, ou pour mesurer le robot.
Moins sûr qu'un programme relu

Il n'y a pas de programme à relire avant de partir : une faute de frappe dans une coordonnée part tout de suite. D'où des garde-fous automatiques, vérifiés avant chaque mouvement depuis la posture lue : atteignabilité, butées et collisions sur tout le chemin, et deux règles que vous fixez vous-même, zone= et pas_max= (section 7). Un refus arrête le mouvement avant que rien ne parte.

Section 02Ce qui bouge : simulateur, robot, ou les deux

Deux paramètres du constructeur, simulateur et robot, disent à qui parle la commande. Les scripts d'exemple appellent ce choix CIBLE, à ne pas confondre avec la cible d'un mouvement.

MontageCe qu'il fautCe qui se passe
simulateur=True, robot=False
par défaut		 le simulateur ouvert (python main.py) chaque commande part à la fenêtre, qui l'anime ; le script attend la fin de l'animation. Si la fenêtre est connectée au robot avec le miroir actif, elle coupe le miroir : la commande vise le modèle, pas le bras.
robot=True, simulateur=False le Dobot branché et allumé, simulateur fermé le script ouvre lui-même le port série, sans fenêtre ; il remplit la file du contrôleur et la suit jusqu'à la fin. Le ratio de vitesse du contrôleur est mis à 100 % : les vitesses de Commande sont absolues.
simulateur=True, robot=True le simulateur ouvert (ou lancer_simulateur=True), le Dobot branché le script demande à la fenêtre de se connecter ; elle exécute chaque commande sur le robot, miroir actif, ratio à 100 %. Le script attend la fin du robot, pas celle de l'animation.
CIBLE = "les-deux"                       # "simulateur", "robot" ou "les-deux"

with Commande(simulateur=CIBLE in ("simulateur", "les-deux"),
              robot=CIBLE in ("robot", "les-deux")) as robot:
    ...

Avec simulateur=False, robot=False, le constructeur lève ValueError : il faut au moins une destination.

lancer_simulateur=True : le script ouvre la fenêtre

Si aucune fenêtre ne répond, le script lance main.py dans un processus séparé et attend sa passerelle, jusqu'à 60 s : Qt veut le fil principal, que le script garde pour attendre ses mouvements. La fenêtre vit ensuite sa vie : un Ctrl+C dans le terminal ne la tue pas, la fin du script ne la ferme pas, et un script relancé la retrouve. Sans ce paramètre, l'absence de fenêtre est une alerte rouge, AUCUN SIMULATEUR OUVERT.

Un simulateur trop ancien

Une fenêtre ouverte avant la mise à jour du dépôt répond à la passerelle mais ignore la commande temps réel : alerte rouge LE SIMULATEUR OUVERT NE CONNAIT PAS LA COMMANDE TEMPS REEL. Fermez-la, relancez python main.py.

fermer() — ou la sortie du bloc with — libère ce que la commande tient : le port série en mode robot seul. La fenêtre, elle, reste ouverte, et garde sa liaison avec le robot s'il y en a une (fiche 1, le panneau robot réel).

Section 03Les neuf exemples, un par un

Ils sont dans examples/controle-temps-reel/, courts et commentés. Chacun prend le montage en argument — ou dans la constante CIBLE en tête du fichier — et aucun ne bouge le robot sans que vous ayez tapé Entrée.

python examples/controle-temps-reel/02_mouvements_simples.py              # simulateur
python examples/controle-temps-reel/02_mouvements_simples.py robot        # robot seul
python examples/controle-temps-reel/02_mouvements_simples.py les-deux     # les deux
Premier essai sur le vrai robot : dans cet ordre
  1. 01 en mode les-deux. Aucun mouvement. Si le robot est en défaut — c'est le cas après chaque mise sous tension — l'assistant de mise en route s'ouvre dans la fenêtre : suivez-le. Puis vérifiez que la pose lue est juste : le modèle 3D doit se superposer au vrai bras.
  2. 02 en mode les-deux, zone dégagée. Rien sur la table entre le repos et les points (220, ±50, 80) ; la main près du bouton d'arrêt du robot, le terminal au premier plan pour Ctrl+C.
  3. Seulement ensuite, 06 et 07 : le mode continu, moins éprouvé que le point à point (section 8).

Les positions des exemples sont prévues pour la ventouse (62 mm). Avec un autre outil, vérifiez-les d'abord dans le simulateur.

01 — Choisir ce qui bouge, lire où en est le bras

01_choisir_la_cible.py ne fait que lire : le montage, le bloc with, pose() et angles(). C'est le seul script qu'on peut lancer sur le robot sans rien dégager.

with Commande(simulateur=CIBLE in ("simulateur", "les-deux"),
              robot=CIBLE in ("robot", "les-deux")) as robot:
    x, y, z, r = robot.pose()          # pointe de la ventouse, mm et degres
    j1, j2, j3, j4 = robot.angles()    # degres, les memes pour robot et modele
Lancer01_choisir_la_cible.py les-deux pour le premier essai ; simulateur pour s'exercer.
ObserverDans le simulateur, bougez un curseur puis Entrée : la pose suit. Sur le robot, comparez la pose affichée au bras réel et au modèle 3D : les angles sont ceux du contrôleur tels quels ; la pose est convertie depuis le repère du contrôleur, dont l'origine est à hauteur d'épaule. Un écart de plusieurs millimètres signale une mise en route mal faite ou une mauvaise longueur d'outil.
PiègesEn mode robot, le simulateur doit être fermé. La pose est celle de la pointe de l'outil : avec un outil d'une autre longueur, passez longueur_outil= (fiche 2, l'outil et le TCP). q puis Entrée pour quitter.

02 — Mouvements simples : chaque appel attend la fin

02_mouvements_simples.py : movj, movl, une durée imposée, une composante omise, le repli. Après chaque mouvement, le script affiche le temps écoulé et la pose relue.

with Commande(..., vitesse=40, vitesse_articulaire=40) as robot:
    robot.movj(AU_DESSUS)            # cible(220, 0, 120) ; attend la fin
    robot.movl(A)                    # cible(220, -50, 80), a 40 mm/s
    robot.movl(B, duree=2.0)         # cible(220, 50, 80), en 2 s
    robot.movl(z=50)                 # x, y et r repris de B
    robot.repli()                    # (0, 15, 30, 0) deg
Lancer02_mouvements_simples.py les-deux, zone dégagée, après 01.
ObserverLe terminal ne rend la main qu'à l'arrêt du bras. Une cible seule part toujours en point à point : l'étape 3 dure environ 2 s, la durée ayant été convertie en vitesse pour le profil trapèze du contrôleur. Le temps affiché comprend aussi la lecture, le contrôle et l'envoi.
Piègesvitesse=40 est en mm/s (movl), vitesse_articulaire=40 en deg/s (movj) : les deux n'ont rien de comparable. Une composante omise reprend la dernière cible commandée, pas la pose relue.

03 — Une cible tapée au clavier

03_cible_au_clavier.py : on tape x y z (ou x y z r), le robot y va en ligne droite. La zone de travail est active, et un refus est attrapé au lieu d'arrêter le script.

ZONE = ((170, 270), (-90, 90), (30, 140))       # mm : x, y, z

with Commande(..., vitesse=40, zone=ZONE) as robot:
    while True:
        ...                                      # lecture de "x y z [r]"
        try:
            robot.movl(cible(*valeurs))          # rend la main a l'arrivee
        except ErreurExecution:
            print("cible refusee, le robot n'a pas bouge")
            continue
Lancer03_cible_au_clavier.py, puis les-deux une fois le principe compris.
ObserverEssayez 220 0 80 (accepté), 400 0 80 (hors zone), 170 0 140 (dans la zone, mais J2 sortirait de ses butées). Chaque refus affiche une alerte rouge qui dit pourquoi, puis le script redemande une cible.
PiègesLa zone est une boîte devant le robot, à adapter au poste. La virgule décimale est acceptée (220,5). Un quatrième nombre tourne l'outil : c'est r, en degrés.

04 — Pas à pas au clavier

04_pas_a_pas_clavier.py : x+, z-… avancent d'un pas ; pas 5 change le pas ; Entrée seule refait le dernier déplacement ; r ramène au repli. La nouvelle cible part de la pose lue.

with Commande(..., vitesse=30, zone=ZONE, pas_max=30) as robot:
    x, y, z, r = robot.pose()
    robot.movl(x=x + dx * pas, y=y + dy * pas, z=z + dz * pas)   # r garde
Lancer04_pas_a_pas_clavier.py — ou les-deux pour régler un poste.
ObserverTapez pas 50 puis x+ : refusé, pas_max vaut 30 mm — une faute de frappe ne lance pas le bras à l'autre bout de la table. r, lui, est accepté même à plus de 30 mm : le repli échappe à pas_max, pas à la zone.
PiègesUne butée frôlée n'est signalée en jaune qu'une fois par séance, pas à chaque pas. Le repli (222, 0, 134 avec la ventouse) doit être dans la zone, sinon il est refusé.

05 — La ventouse, les sorties et les entrées

05_ventouse_et_es.py : une prise et dépose étape par étape, puis la sortie EIO18 allumée et éteinte, puis l'entrée EIO17 lue à la demande.

HAUT = hg.translation(0, 0, -50)    # 50 mm plus haut : z de l'outil vers le bas

robot.movj(PRISE @ HAUT)
robot.movl(PRISE)
robot.ventouse(True)                # rend la main une fois l'outil actionne
robot.movl(PRISE @ HAUT)
...
robot.sortie(PORT_SORTIE, True)
print(robot.entree(PORT_ENTREE))    # lue sur la machine, a l'instant
Lancer05_ventouse_et_es.py ; sur le robot, après avoir vérifié ce qui est branché sur EIO17 et EIO18.
ObserverDans le simulateur, la ventouse s'affiche active d'une commande à l'autre ; la sortie s'allume dans le panneau Entrées / Sorties, et l'entrée se bascule à la main en cliquant sur EIO17. Sur le robot, le port est configuré en entrée au premier entree().
PiègesLa ventouse n'est pas une sortie EIO : elle a sa propre commande, choisie d'après l'outil déclaré (outil="ventouse"). Relâchée, elle laisse la pompe tourner : ventouse(False, couper=True) l'arrête une seconde après. Ce script n'emploie pas la pince ; avec outil="pince", pince(False) coupe la pompe d'elle-même (couper_pompe). Une sortie peut commander un vérin ou un convoyeur. Le dégagement s'écrit avec un z négatif, parce que l'axe z de l'outil pointe vers le bas (fiche 2, fabriquer une cible).

06 — Plusieurs cibles avec leurs durées : continu ou pas

06_plusieurs_cibles.py : un carré de 100 × 70 mm parcouru deux fois, en point à point puis en trajectoire continue, avec une durée par côté ; puis sans durées, à 60 mm/s ; puis une durée impossible.

CARRE = [(COINS[1], 2.0), (COINS[2], 1.5), (COINS[3], 2.0), (COINS[0], 1.5)]

robot.movl(CARRE, continu=False)    # arret a chaque coin
robot.movl(CARRE, continu=True)     # sans arret : c'est le defaut
robot.movl(COINS[1:] + COINS[:1], vitesse=60)
robot.movl([(COINS[1], 0.5), COINS[2], COINS[3], COINS[0]])   # 100 mm en 0,5 s
Lancer06_plusieurs_cibles.py, puis les-deux après 01 et 02.
ObserverSur le robot, regardez et écoutez les coins : arrêt franc en point à point, passage sans arrêt en continu. Le chronomètre affiche la durée réelle ; le simulateur prévoit 7,00 s en point à point et environ 7,10 s en continu, pour 7,00 s demandées. La dernière ligne donne l'avertissement jaune :
1 MOVL : 0.50 s demandees, ~1.06 s en realite (vitesse plafonnee a 125 mm/s).
PiègesUn élément de la liste est une cible, ou un couple (cible, durée) ; sans durée, c'est la vitesse qui décide. Le chronomètre du script compte aussi la préparation : comparez les ordres de grandeur, pas les centièmes.

07 — Arcs de cercle et coins arrondis

07_arc_et_lissage.py : un demi-cercle, puis un cercle complet en deux demi-cercles, puis un zigzag sans et avec lissage.

robot.movc(DROITE, HAUT_CERCLE, duree=3.0)                    # via, fin
robot.movc([(GAUCHE, BAS_CERCLE, 2.5), (DROITE, HAUT_CERCLE, 2.5)])
robot.movl(ZIGZAG[1:], lissage=0, vitesse=50)
robot.movl(ZIGZAG[1:], lissage=60, vitesse=50)                # coins coupes
Lancer07_arc_et_lissage.py, puis les-deux après 06.
ObserverUn arc, même seul, part en trajectoire continue : des points tous les 5 mm, parcourus sans arrêt. Prévisions du simulateur : demi-cercle de 3,00 s à environ 55 mm/s, cercle de 5,00 s ; zigzag de 3,85 s sans lissage, 3,55 s à 60 %. Le modèle prévoit que le robot ralentisse nettement à chaque coin vif, beaucoup moins une fois arrondi : à vérifier sur la machine.
PiègesAvec lissage, le robot ne passe plus exactement par les cibles (fiche 2, le lissage). Un arc qui fait tourner l'outil part par l'arc du contrôleur, à la vitesse moins bien tenue : c'est annoncé en jaune. Le ralentissement en courbe n'est calé que sur une mesure.

08 — Le simulateur et le robot, simulateur lancé par le script

08_simulateur_et_robot.py : le script trouve la fenêtre, ou l'ouvre, lui demande de se connecter au robot, puis lui confie chaque commande.

with Commande(simulateur=True, robot=(CIBLE == "les-deux"),
              lancer_simulateur=True,   # ouvre main.py s'il n'est pas ouvert
              port=None,                # None : premier port serie trouve
              vitesse=40) as robot:
    robot.movj(A)
    robot.movl([B, A])
Lancer08_simulateur_et_robot.py (les-deux par défaut) ; simulateur pour essayer sans robot. Le mode robot seul n'a pas de sens ici.
ObserverLa fenêtre s'ouvre si besoin ; robot en défaut : le terminal dit terminez la MISE EN ROUTE dans la fenetre du simulateur et attend. Le modèle suit le vrai bras. À la fin, la fenêtre reste ouverte et garde la liaison : relancez le script, il la retrouve.
PiègesSi un autre script tient déjà le port (mode robot seul), la fenêtre ne peut pas se connecter. port="COM4" ou port="/dev/ttyUSB0" quand plusieurs ports sont présents.

09 — Les garde-fous

09_garde_fous.py : sept mouvements, dont cinq refusés pour cinq raisons différentes, puis un mouvement lent de 12 s à interrompre au Ctrl+C. Ce que donne chaque essai, avec zone=((170, 270), (-90, 90), (30, 140)) et pas_max=100 :

3. (400, 0, 80)refusé hors de la zone de travail : la zone est jugée avant l'atteignabilité

Section 04Référence de Commande

Les entrées se lisent comme celles de la fiche 3. Toutes les longueurs sont en millimètres, tous les angles en degrés.

from dobot_sim import Commande, ErreurExecution, cible

Construire la commande

Commande(simulateur=True, robot=False, vitesse=50.0, port=None, lancer_simulateur=False, zone=None, pas_max=None, outil="ventouse", longueur_outil=None, vitesse_articulaire=50.0, acceleration=400.0, acceleration_articulaire=400.0, lissage=0.0, continu=True)

Se connecte au montage choisi, puis lit la pose : c'est d'elle que partent les composantes omises du premier mouvement. Les réglages servent de valeurs par défaut à tous les mouvements, et se changent ensuite par regler().

simulateur bool
Passer par la fenêtre du simulateur (section 2).
robot bool
Exécuter sur le robot réel. Seul, le script ouvre le port ; avec simulateur=True, c'est la fenêtre.
vitesse float
En mm/s : movl et movc, en point à point comme en continu.
port str
Port série du robot, "COM4", "/dev/ttyUSB0"… None : le premier trouvé. Ignoré sans robot=True.
lancer_simulateur bool
Ouvrir main.py dans un autre processus si aucune fenêtre ne répond.
zone 3 couples
((xmin, xmax), (ymin, ymax), (zmin, zmax)) en mm, chaque min < max. Toute cible, et tout trajet, qui en sortirait est refusé (section 7). None : pas de zone.
pas_max float
Distance maximale, en mm, entre une cible et la précédente. None : pas de limite.
outil str
Outil monté, au catalogue : "aucun", "ventouse", "pince", "stylo", "laser".
longueur_outil float
Longueur réelle de l'outil, en mm. None : celle du catalogue, 62 mm pour la ventouse.
vitesse_articulaire float
En deg/s : tout movj, en point à point comme en continu, et le repli.
acceleration float
En mm/s². Elle sert aussi au mode continu : c'est elle qui décide si la vitesse demandée est atteinte (section 6).
acceleration_articulaire float
En deg/s², pour un movj point à point.
lissage float
Arrondi des raccords entre les cibles d'une liste, de 0 à 100 %.
continu bool
True : une liste de cibles s'enchaîne sans arrêt ; False : arrêt à chaque cible.

Lève ValueError sans aucune destination, ou pour une zone mal formée ; ErreurExecution si aucun simulateur ne répond, si la connexion au robot échoue, ou si le robot reste en défaut après la mise en route.

Les mouvements

Tous rendent la main à l'arrivée, et renvoient la commande elle-même : ils s'enchaînent si on le souhaite. Un refus lève ErreurExecution sans que rien ne parte.

movj(T=None, *, x=None, y=None, z=None, r=None, q=None, duree=None, vitesse=None, lissage=None, continu=None, repere=None, commentaire="")

Mouvement articulaire : les angles sont interpolés, le chemin de la pointe n'est pas rectiligne.

T cible ou liste
Une cible (section 5), ou une liste de cibles, chacune éventuellement accompagnée de sa durée.
x, y, z, r float
Surchargent la cible composante par composante. Interdits avec une liste.
q q
Configuration articulaire imposée, [J1, J2, J3, J4] en degrés : le MGI n'est pas appelé.
duree float
Durée imposée, en s. Avec une liste : celle des éléments qui n'ont pas la leur.
vitesse float
En deg/s, plafonnée à 200 deg/s en point à point. Dans une liste en continu, elle fixe la durée de chaque movj — celle que le simulateur lui donne à cette vitesse articulaire —, et c'est cette durée que la course tient, dans la limite de 125 mm/s pour la pointe : un avertissement jaune le dit quand elle est trop courte.
lissage, continu float, bool
Pour une liste : remplacent les réglages de la commande le temps de cet appel.
repere, commentaire str
Repris de Pilote. Commande n'a pas de repère objet : laissez repere de côté.
robot.movj(PRISE)                       # une cible
robot.movj(x=220, y=-50, z=80)          # des coordonnees
robot.movj(q=[0, 15, 30, 0])            # des angles
robot.movj([A, (B, 2.0), C])            # plusieurs cibles, sans arret

Voir fiche 3, movj exemple 02

movl(T=None, *, x, y, z, r, duree, vitesse, lissage, continu, repere, commentaire)

Mouvement rectiligne : la pointe suit une droite. Mêmes paramètres que movj, sans q ; vitesse en mm/s, plafonnée à 125 mm/s, la plus haute vitesse mesurée.

robot.movl(PRISE)
robot.movl(z=40)                                  # descente verticale
robot.movl([(A, 1.0), (B, 0.5), C])               # cible, duree en s
robot.movl([A, B, C], lissage=50)                 # coins arrondis
robot.movl([A, B, C], continu=False)              # arret a chaque cible

Voir fiche 3, movl exemple 03 exemple 06

movc(via, T=None, *, x, y, z, r, duree, vitesse, lissage, continu, repere, commentaire)

Arc de cercle partant de la position actuelle, passant par via et finissant en T. Un arc, même seul, est suivi en trajectoire continue, ce qui en maîtrise la vitesse ; s'il fait tourner l'outil, il passe par l'arc du contrôleur, et c'est annoncé.

via cible ou liste d'arcs
Le point de passage. Ou, T omis, une liste d'arcs (via, fin) ou (via, fin, duree).
T cible

Outil, entrées / sorties, attente

actionner(actif=True)  ·  ventouse(actif=True, couper=False)  ·  pince(fermee=True, couper=True)

Commande l'outil monté, et rend la main une fois la commande faite. Sur le robot, c'est une commande à part : jamais au milieu d'une trajectoire continue.

actif, fermee bool
True : aspirer, fermer, allumer ; False : relâcher, ouvrir, éteindre.
couper bool
Au relâchement de la ventouse ou à l'ouverture de la pince seulement : la pompe à air est coupée 1 s après (DELAI_COUPURE_POMPE), le temps que la pince s'ouvre ou que la pièce soit chassée. Le script n'attend pas : une minuterie s'en charge en arrière-plan, et le mouvement suivant peut partir pendant cette seconde. Par défaut True pour la pince, False pour la ventouse. Sans effet à la prise, et sans robot réel.

Une nouvelle action sur l'outil avant l'échéance — par exemple pince(True) pour reprendre une pièce — annule la coupure prévue : couper la pompe d'une pince qu'on vient de refermer lui ferait lâcher sa pièce. Un appel direct à couper_pompe() l'annule aussi, puisqu'il coupe tout de suite. fermer() — donc la fin d'un bloc with — attend l'échéance d'une coupure encore prévue et l'envoie avant de fermer la liaison. couper=False laisse la pompe tourner.

C'est l'outil déclaré qui compte, pas le nom de la méthode

ventouse() et pince() sont des alias d'actionner(). La commande envoyée au robot dépend de l'outil déclaré dans le constructeur : avec Commande(..., outil="pince"), robot.ventouse(True) ferme la pince ; avec l'outil par défaut, "ventouse", robot.pince(True) fait aspirer la ventouse. Déclarez l'outil réellement monté. Pour "laser", c'est le laser ; pour tous les autres outils, la commande de la ventouse.

Voir fiche 3, actionner exemple 05

couper_pompe()

Arrête la pompe à air, de la ventouse et de la pince, tout de suite : deux commandes immédiates, hors de la file du contrôleur, qui agissent même pendant un mouvement. Sans robot réel, elle ne fait rien : le simulateur n'a pas de pompe.

Pourquoi il le faut. Relâcher la ventouse ou ouvrir la pince n'éteint pas la pompe : la commande envoyée garde l'outil commandé (isCtrlEnable = 1) en le mettant au repos (isGripped = 0), et la pompe souffle, pour chasser la pièce ou ouvrir les doigts ; puis elle continue de tourner, avec son bruit. Seul isCtrlEnable = 0 l'arrête : c'est ce qu'envoie couper_pompe().

Une pièce tenue est lâchée

Couper la pompe d'une ventouse qui aspire, ou d'une pince fermée, fait tomber la pièce. À n'appeler qu'une fois la pièce posée — ou laisser faire pince(False), qui la coupe d'elle-même une seconde après l'ouverture, et ventouse(False, couper=True), qui fait de même au relâchement.

robot.movl(DEPOSE)
robot.ventouse(False, couper=True)    # relache ; pompe coupee 1 s apres
robot.movl(DEPOSE @ HAUT)             # part tout de suite, sans attendre

robot.pince(False)                    # ouvre ; coupure automatique 1 s apres
robot.pince(False, couper=False)      # ouvre, la pompe continue de tourner

Le panneau Robot réel de la fenêtre a le même geste : le bouton Couper la pompe.

Lève ErreurExecution (ARRET DE LA POMPE IMPOSSIBLE) si la liaison ne répond pas.

fermer()  ·  with Commande(…) as robot

Libère ce que la commande tient : le port série en mode robot seul. La fenêtre du simulateur reste ouverte, avec sa liaison. Fermer deux fois ne fait rien. Deux façons de s'en servir :

# 1. le bloc with : RECOMMANDE. fermer() est appele a la sortie du bloc,
#    meme apres une erreur ou un Ctrl+C
with Commande(simulateur=True, robot=True, vitesse=40) as robot:
    robot.movj(cible(220, 0, 80))
    robot.repli()

# 2. sans with : utile en console interactive, ligne a ligne
robot = Commande(simulateur=True, robot=True, vitesse=40)
robot.movj(cible(220, 0, 80))
robot.pose()
robot.fermer()                       # a ne pas oublier

Sans with, une erreur qui arrête le script saute le fermer() ; en mode robot seul, le port est tout de même refermé à la fin du processus, mais une console interactive, elle, ne se termine pas : fermez à la main avant de relancer un autre script sur le même port.

Lève RuntimeError si l'on se sert de la commande une fois fermée.

Deux attributs se lisent : direct, vrai quand le script tient lui-même la liaison, et processus_simulateur, le processus de la fenêtre si c'est le script qui l'a lancée.

Section 05Cibles, listes de cibles, options par appel

Mêmes cibles que Pilote : une matrice homogène 4×4 de préférence (fiche 2, fiche 3), ou des coordonnées.

Une cible

robot.movl(T) une matrice 4×4 — la forme recommandée. Elle peut aussi être écrite en listes imbriquées : une liste 4×4 dont la dernière ligne vaut (0, 0, 0, 1) est reconnue comme une matrice.

La dernière cible commandée, pas la pose lue

La commande mémorise sa dernière cible. Au départ, c'est la pose lue ; ensuite, c'est la cible du dernier mouvement réussi : un refus la laisse où elle était. regler_longueur_outil() la relit sur la machine. Pour repartir de la position réelle, lisez-la et donnez-la : x, y, z, r = robot.pose(), comme le fait l'exemple 04.

Section 06Le mode continu

Le contrôleur du Magician a deux façons d'aller d'un point à l'autre. En point à point (PTP), il s'arrête à chaque cible. En trajectoire continue (CP), il enchaîne des points sans s'arrêter. Une liste de cibles part en CP par défaut.

Le principe

  1. Le simulateur calcule la trajectoire, avec son propre moteur : durées, arcs, lissage, movj compris. C'est le même calcul que pour un programme de Pilote.
  2. Il l'échantillonne en points : tous les 5 mm le long d'une courbe ; une droite ne garde que ses extrémités. Le tout premier point est placé à 1 mm du départ, pour adoucir le démarrage. Un coin tombe exactement sur la cible.
  3. Chaque portion reçoit sa vitesse, celle qui tient sa durée. Elle est transmise par le réglage junctionVel de SetCPParams, mis en file juste avant les points de la portion : la vitesse change en route, sans arrêt.
  4. Les points partent en file (SetCPCmd, coordonnées absolues du contrôleur), versés au fil de l'eau : la file du contrôleur ne tient que 32 commandes.

Prévoir avant de partir

Avant le départ, la commande prévoit la durée de chaque portion (prevoir_cp) : chaque tronçon vise sa vitesse, chaque jonction est plafonnée par un modèle de virage, le robot part et finit à l'arrêt, et n'accélère ni ne freine plus fort que acceleration. Les vitesses sont ajustées jusqu'à ce que la durée prévue colle à la durée demandée — jusqu'à 125 % de la vitesse nominale pour rattraper un changement de vitesse, jamais au-delà de la vitesse nominale quand c'est la courbure qui freine.

Ce qui ne peut pas tenir est dit en jaune, avec la durée réaliste et sa cause ; c'est alors cette durée que joue le simulateur :

/!\ duree ou vitesse non tenable : le robot fera au mieux
      1 MOVL : 0.50 s demandees, ~1.06 s en realite (vitesse plafonnee a 125 mm/s)
      duree prevue de l'ensemble : ~7.17 s

Trois causes possibles : vitesse plafonnee a 125 mm/s, acceleration 400 mm/s2, ou courbure ou angle : le robot ralentit aux jonctions. Une durée est jugée tenue à 3 % + 0,05 s près. En point à point, la durée demandée devient la vitesse qui fait durer le trapèze du contrôleur ce temps-là : durée = L / v + v / a.

Section 07Les garde-fous et les messages

Avant chaque mouvement, depuis la posture lue sur la machine — et non celle que le script croit —, dans cet ordre. Le premier contrôle qui échoue arrête tout : rien n'est parti.

  1. Les règles du script, cible par cible. La zone : chaque cible, et le point de passage d'un arc. Puis le pas maximal : la distance en ligne droite entre une cible et la précédente — la pose lue pour la première, la cible d'avant pour les suivantes d'une liste. repli() en est exempté, pas de la zone.
  2. La mécanique, cible par cible. Le MGI, appelé sans tolérance : une cible hors d'atteinte est refusée, au lieu d'être ramenée au point le plus proche. Puis les butées.
  3. Tout le chemin. La trajectoire complète, échantillonnée : butées, plan de pose, embase, colonne, et le bras contre lui-même (auto-collision). Puis la zone sur tout le trajet — si le départ y est déjà : un départ hors zone (le repli, la pose d'une séance précédente) n'est pas une faute, on ne juge alors que les cibles.
  4. Les réserves, en jaune. Les annonces (outil qui tourne, lissage ignoré), les durées non tenables, les survitesses, les butées frôlées — celles-ci une seule fois par séance. Le mouvement part.

Un refus : alerte rouge, puis ErreurExecution

!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!
!!! MOUVEMENT REFUSE : cible hors de la zone de travail
!!!     1 MOVL (220, 120, 80) : y = 120.0 hors de [-90 ; 90]
!!!     zone : x [170 ; 270], y [-90 ; 90], z [30 ; 140]
!!!     rien n'a ete envoye
!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!!

Puis l'exception ErreurExecution arrête le script : la suite partirait d'une posture qui n'est pas celle prévue. Pour continuer malgré tout, on l'attrape :

from dobot_sim import Commande, ErreurExecution, cible

with Commande(simulateur=True, robot=False, zone=((170, 270), (-90, 90), (30, 140))) as robot:
    for x, y, z in [(220, 0, 80), (220, 120, 80), (240, 40, 80)]:
        try:
            robot.movl(cible(x, y, z))
        except ErreurExecution as e:
            print("refusee :", e)            # le robot n'a pas bouge
            continue
        print("arrive :", robot.pose())

Un refus ne touche pas la mémoire des cibles : un movl(z=60) qui suit repart de la dernière cible atteinte.

Les messages jaunes

Ils commencent par /!\ et laissent partir le mouvement : durée non tenable (section 6), segment repassé en point à point, lissage ignoré, survitesse, butée frôlée. Après le mouvement, sur le robot, un dernier contrôle compare la position atteinte à la position attendue : au-delà de 2 mm d'écart, le robot s'est arrete a N mm de la cible.

Robot en défaut : l'assistant de mise en route

C'est le cas après chaque mise sous tension : les capteurs d'angle du bras sont faux à l'allumage. Rien ne part tant qu'un défaut reste ; l'assistant s'ouvre — dans la fenêtre du simulateur en mode les-deux, en fenêtre autonome en mode robot seul — et conduit trois étapes, dans cet ordre :

  1. Déclarer une posture de référence, rien ne bouge : l'équerre (bras arrière vertical, avant-bras horizontal), ou les butées arrière, plus reproductibles.
  2. Prise d'origine : le bras parcourt sa course pour recaler J1.
  3. Effacer les défauts et comparer le miroir au vrai bras.

En mode les-deux, le terminal l'annonce une fois et attend. Si le défaut persiste à la fermeture : alerte rouge, rien n'est parti.

Ctrl+C : arrêt d'urgence

Pendant un mouvement, Ctrl+C dans le terminal du script — ou le bouton stop de VS Code, qui envoie SIGTERM — coupe le mouvement avant que le script ne s'arrête : la file du contrôleur est vidée, le robot s'arrête où il est.

!!! ARRET D'URGENCE : mouvement coupe, file du controleur videe
!!!     le robot est arrete la ou il etait ; verifiez sa posture avant de relancer

En simulateur seul, c'est SIMULATION INTERROMPUE : l'animation s'arrête, et le robot qu'on piloterait à côté n'est pas touché. Puis KeyboardInterrupt remonte au script ; l'exemple 09 l'attrape pour quitter proprement.
