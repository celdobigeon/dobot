Matrices homogènes

Le strict nécessaire pour écrire une cible : repérer un solide, passer d'une base à l'autre, composer deux transformations, et reconnaître dans A @ B du programme la T01 · T12 du cours. Les notations sont celles du cours de modèle géométrique.

00 Comment on les écrit

La règle vaut pour tout ce qui se fait sous le Dobot : une cible, un repère, une transformation se déclarent sous forme de matrice 4×4 écrite en clair, dernière ligne comprise.

DEPOSE = np.array([[1,  0,  0,       140.0],
                   [0, -1,  0,       200.0],
                   [0,  0, -1,   EPAISSEUR],
                   [0,  0,  0,         1.0]], dtype=float)

Et non hg.translation(...) @ hg.rot_x(...) comme déclaration. Un produit de fonctions cache les seize nombres au moment précis où il faut les voir : une colonne par axe, la position en quatrième colonne, et le 0 0 0 1 qu'on oublie.

Le produit reste, mais comme justification : il dit d'où viennent les nombres, et il se vérifie.

# un demi-tour autour de x, a cet endroit
assert np.allclose(DEPOSE,
                   hg.translation(140.0, 200.0, EPAISSEUR) @ hg.rot_x(np.pi))

Une seule exception : la composition de repères — PRISE = MAGASIN @ DANS_LE_MAGASIN — où chaque facteur est déjà une 4×4 écrite en clair, et où le produit est précisément ce qu'on cherche à montrer.

01 Repérer un solide

Un solide ne se situe pas par un point : il faut aussi dire comment il est tourné. On lui attache donc une base B1 — trois vecteurs orthonormés et une origine O1 — et on la situe par rapport à une base fixe B0.

Un même point P a donc deux jeux de coordonnées. L'exposant à gauche dit dans quelle base on le lit :

0P les coordonnées de P dans la base fixe B0
1P les coordonnées du même point dans B1

Le point n'a pas bougé. Changer de base ne déplace rien : cela change la façon de nommer le même endroit. C'est la première chose à se redire quand un résultat paraît absurde.

02 La matrice de passage

Pour exprimer dans B0 ce qu'on connaît dans B1, il faut savoir où pointent les axes de B1, vus de B0. On les range en colonnes : c'est la matrice de passage R01.

R01 =
uxvxwx uyvywy uzvzwz

Colonne 1 : le vecteur u de B1, lu dans B0. Colonne 2 : v. Colonne 3 : w. Rien d'autre.

D'où la règle de lecture qui sert tous les jours :

Une colonne est un axe ; une ligne est une composante. La colonne j dit où pointe le j-ième axe du repère décrit. La ligne i dit ce que chacun de ces axes vaut selon le i-ième axe du repère de référence.

Entre bases orthonormées, l'opérateur est orthogonal : son inverse est sa transposée.

R10 = R01−1 = R01T

C'est gratuit, et c'est une vérification : R @ R.T doit rendre l'identité.

03 La transformation homogène

La rotation ne suffit pas : les deux origines ne sont pas au même endroit. On range donc rotation et position dans une seule matrice 4×4, T01, dite « de passage de B0 à B1 ».

T01 =
r₁₁r₁₂r₁₃px r₂₁r₂₂r₂₃py r₃₁r₃₂r₃₃pz 0001

Le bloc 3×3 est la rotation ; la quatrième colonne est la position de O1 dans B0, en millimètres. La dernière ligne vaut toujours (0, 0, 0, 1) — c'est elle qu'on oublie d'écrire.

Le changement de repère s'écrit alors en une ligne, le point étant complété par un 1 :

0P = T01 · 1P

Pourquoi le 1 en bas. Sans lui, une matrice ne saurait qu'orienter. La quatrième coordonnée transforme la translation en multiplication : c'est ce qui permet de composer des déplacements au lieu de les additionner à part.

04 Les trois rotations

Les colonnes portent les axes du repère tourné (u, v, w), les lignes celles du repère fixe (x, y, z). On retrouve à chaque fois le même motif, décalé d'un cran.

Rx(α) =
100 0cos α−sin α 0sin αcos α
Ry(φ) =
cos φ0sin φ 010 −sin φ0cos φ
Rz(θ) =
cos θ−sin θ0 sin θcos θ0 001

L'axe de la rotation garde sa colonne et sa ligne intactes : une colonne (1, 0, 0) pour Rx, (0, 1, 0) pour Ry, (0, 0, 1) pour Rz. C'est le moyen le plus rapide de vérifier qu'on n'a pas confondu deux d'entre elles.

Dans le simulateur, elles sont déjà écrites, en 4×4 et en radians :

from dobot_sim import homogeneous as hg

hg.rot_x(np.pi)                 # un demi-tour autour de x
hg.rot_z(np.radians(38))        # 38 degres autour de z
hg.translation(140, 200, 10)    # en millimetres
hg.identite()

05 Composer, et de quel côté

Deux changements de repère enchaînés se multiplient, et les indices se recollent :

T02 = T01 · T12

Le 1 de droite et celui de gauche s'annulent : de 0 à 1, puis de 1 à 2, donc de 0 à 2. Si vos indices ne se recollent pas, le produit est dans le mauvais sens.

LA RÈGLE QUI DÉCIDE DE TOUT. Une matrice écrite à droite agit dans le repère que les précédentes viennent de construire ; écrite à gauche, elle agit dans le repère de départ.

Un exemple qui revient dans toutes les activités : on tourne une pièce de a autour de la verticale, puis on retourne l'outil pour qu'il descende dessus.

cible = hg.rot_z(a) @ hg.rot_x(np.pi)

Le Rx(180°) est à droite : il tourne donc autour du u du repère intermédiaire, et non autour du x fixe. L'axe du demi-tour ne bouge pas, les deux autres se retournent :

après Rz(a)puis Rx(180°) autour de u
colonne 1u = (cos a, sin a, 0)inchangée
colonne 2v = (−sin a, cos a, 0)−v = (sin a, −cos a, 0)
colonne 3w = (0, 0, 1)−w = (0, 0, −1)

À essayer une fois, pour ne plus hésiter. Les deux ordres ne donnent pas la même matrice — le second tourne autour du x fixe.

print(hg.rot_z(a) @ hg.rot_x(np.pi))   # autour de u
print(hg.rot_x(np.pi) @ hg.rot_z(a))   # autour du x fixe

06 Du cours au programme

Le programme ne numérote pas ses repères : il les nomme. C'est la seule différence.

Le cours écritLe programme écritEt cela veut dire
T01 MAGASIN où est le magasin, vu de la base du robot
T12 DANS_LE_MAGASIN où est la pièce, vue du magasin
T02 = T01·T12 PRISE = MAGASIN @ DANS_LE_MAGASIN où est la pièce, vue de la base

Le @ de Python est le produit matriciel. Il se lit de gauche à droite comme une phrase : le magasin, puis la pièce dans le magasin.

Deux emplois reviennent sans cesse :

REPERE @ DEDANS situer : une cible exprimée dans un repère de travail
CIBLE @ HAUT décaler : un dégagement exprimé dans le repère de l'outil, puisque la matrice est à droite

Le z de l'outil pointe vers le BAS : c'est sa direction d'approche. Un dégagement vers le haut s'écrit donc avec un z négatif.

HAUT = hg.translation(0, 0, -80)
assert (CIBLE @ HAUT)[2, 3] > CIBLE[2, 3], "le degagement descend !"

07 Vérifier une matrice

Quatre contrôles, trente secondes, et ils attrapent la quasi- totalité des fautes d'écriture.

R = T[:3, :3]

np.allclose(np.linalg.norm(R, axis=0), 1)     # colonnes unitaires
np.allclose(R.T @ R, np.eye(3))               # et orthogonales
np.isclose(np.linalg.det(R), +1)              # direct, pas un miroir
np.allclose(T[3], [0, 0, 0, 1])               # la ligne oubliee

Un déterminant de −1 n'est pas une rotation mais une symétrie : vous avez retourné un nombre impair d'axes. Le demi-tour de l'outil en retourne deux — y et z — et reste donc à +1.

Et l'inverse d'une transformation homogène, quand on a besoin de lire dans l'autre sens :

hg.inverse(T)        # et non np.linalg.inv : plus sur, et plus rapide

08 Les cinq pièges

L'ordre A @ B et B @ A diffèrent. Vérifiez que vos indices se recollent.
Le côté À droite : dans le repère qu'on vient de construire. À gauche : dans celui de départ.
Degrés ou radians hg.rot_z prend des radians. Une cote d'atelier est en degrés : np.radians(...).
La dernière ligne Une 4×4 sans sa ligne (0, 0, 0, 1) n'est pas homogène, et le produit donnera n'importe quoi.
Le sens du z Repère de table : z vers le haut. Repère d'outil : z vers le bas. Ce ne sont pas les mêmes objets.
